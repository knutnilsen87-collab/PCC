3. FACTS AND CAUSAL BRIDGE
============================================================

facts:
  - Previous implementation only prepared a renderer adapter and still relied on a Vite browser tab for launch.
  - The previous repo start command could still fall back to starting Vite and opening localhost.
  - Browser folder input can trigger "Vil du laste opp X filer til dette nettstedet?" and is unacceptable for PCC production desktop.
  - Electron provides a Windows .exe runtime and native folder picker via dialog.showOpenDialog.
  - The renderer already consumes safe ScannableEntry records and creates ProjectAnalysisSnapshot through the existing import pipeline.
  - Assistant responses were previously rendered in the bottom bar, making longer instructions hard to read while using the project surface.
  - The packaged desktop window needed explicit comfortable desktop sizing.
  - A fixed 1440px width still appears too small on ultrawide/high-resolution desktop screens.

causal_bridge:
  problem_observed: User reported that PCC still starts far too small on the desktop.
  hypothesized_cause: The prior enforced bounds still capped width at 1440px, which is small on the user's display.
  change_made: Replaced the fixed width/height cap with work-area-relative sizing: roughly 90% width and 88% height, with safe margins and minimum size.
  expected_effect: PCC launches as a large centered desktop workspace on both normal and ultrawide displays while still not being fullscreen.
  evidence_that_effect_happened:
    - corepack pnpm typecheck: pass

    - corepack pnpm desktop:smoke after ultrawide-scaled window bounds: pass
    - corepack pnpm lint: pass
