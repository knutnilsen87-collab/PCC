3. FACTS AND CAUSAL BRIDGE
============================================================

facts:
  - Previous implementation only prepared a renderer adapter and still relied on a Vite browser tab for launch.
  - The previous repo start command could still fall back to starting Vite and opening localhost.
  - Browser folder input can trigger "Vil du laste opp X filer til dette nettstedet?" and is unacceptable for PCC production desktop.
  - Electron provides a Windows .exe runtime and native folder picker via dialog.showOpenDialog.
  - The renderer already consumes safe ScannableEntry records and creates ProjectAnalysisSnapshot through the existing import pipeline.
  - Imported projects were still routed through ImportedProjectOverview, which caused the old setup/import-result layout to appear after import.

causal_bridge:
  problem_observed: After successful desktop import, PCC returned to the old import result/setup layout instead of the Project Profile layout.
  hypothesized_cause: ProjectSurface had a special-case branch that rendered ImportedProjectOverview whenever a local-folder analysis existed.
  change_made: Removed the imported-project special-case route, let imported projects render through ProjectProfilePage, included the Project Profile command bar for imported projects, and added a regression test for imported project rendering.
  expected_effect: After selecting a folder, the project appears in the sidebar/header and the main surface is the Project Profile with Current Focus, Next Action, Vital Signs, Milestones, Workstreams, Risks, Artifacts and AI command bar.
  evidence_that_effect_happened:

    - corepack pnpm desktop:smoke after repackaging: pass

  causality_confidence: high
